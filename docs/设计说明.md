# 设计说明

本文说明 lua-async-dialect 的动机、**嵌入式方言**模型、转译管线（splice）、状态机与控制流降级、
**取消 / try-catch / 组合子 / Delay / forget**，以及与协程方案的对比。

## 1. 动机

Lua 里写异步常见两条路：显式回调 / Promise 链，或 `coroutine` + 调度器。本项目走第三条：
**源码层提供 C# 风格 `async` / `await`，编译期降到表状态机 + Task**，且把方言嵌在标准 Lua 宿主文件中。

## 2. 嵌入式方言模型

`.alua` 类似「Makefile 嵌入 recipe」：

- **宿主**：大部分源码是**逐字透传**的标准 Lua。
- **方言块**：仅顶层 `async function Name(...) ... end` 被抽出，走 Lexer → Parser → Codegen。
- **顺序**：透传块与生成块按源码出现顺序拼接；若存在任一 async，在输出**最顶部**插入一次 `local Task = require("runtime.task")`。

实现见 `lib/splice.lua`：字符级扫描；块关键字含 `function`/`if`/`do`/`try`/`repeat`。

| 层 | 职责 | 位置 |
| --- | --- | --- |
| **Splice** | 找 async 区域、透传、拼装 | `lib/splice.lua` |
| **方言** | async 体内语法与语义 | `lib/lexer.lua` 等 |
| **运行时** | Task / 取消 / 错误形状 | `runtime/*.lua` |

**嵌套 async**：不支持 `local async function`（splice 只识别顶层 `async function`）。
从宿主 Lua 调用已生成的 async 函数（返回 Task）即可组合。

## 3. 转译管线

```
.alua → Splice → text | async →（async：Lexer→Parser→Codegen）→ 拼接输出
```

## 4. 状态机模型

每个 `async function` 生成 `sm:step(ok, val)`：

- `ok == true`：恢复 await 临时量，继续状态。
- `ok == false` / `"canceled"`：若当前 await 登记了 try 失败出口 → 跳 catch/finally；否则 `Task.rejected` / `Task.canceled`。
- **无协程**：挂起 = return Task；恢复 = 回调再入 `step`。

`try/catch/finally` 降为 label：失败时设 `_err` / `_err_kind`，finally 出口处理 `_propagate` 与 `_has_return`。

## 5. Task 运行时

状态：`pending` → `fulfilled` | `rejected` | `canceled`。

- `andThen(ok, err, cancel)`：缺省 cancel 回调时**向下游传播 canceled**（不落入 err）。
- `Task.await_then`：三路回调对应 `step(true|false|"canceled", …)`。
- `defer` / `pump`：微任务队列；`pump` 同时触发已到期的内部定时器。

### Delay 与时钟

| API | 作用 |
| --- | --- |
| `Task.delay(ms, ct?)` | ms 后兑现为 `ms`；尊崇显式 / ambient 取消 |
| `Task.set_timer(fn)` | 宿主钩子：`fn(callback, ms) -> cancel_fn?` |
| 内部定时器堆 | 无宿主 timer 时由 `delay` 注册；`pump` / `advance` 触发 |
| `Task.now()` / `Task.set_clock(fn)` | 默认虚拟毫秒时钟；可注入 |
| `Task.advance(ms)` | 虚拟时钟前进并触发到期项（demo / 测试） |
| `Task.next_timer_delay()` | 距下一未取消定时器的 ms |
| `Task.reset_scheduler()` | 清空队列与堆（demo 隔离） |

故事：**一套堆 + 可选宿主 timer**；无真实 sleep 时用虚拟时间。

### FromException / forget / 未观察拒绝

- `Task.from_exception` / `faulted` → `rejected`；`from_canceled` → `canceled`。
- `task:forget()`：标记已观察并吞掉失败（类 C# `async void`，**慎用**）。
- 若 Task **reject/cancel** 且从未被 `andThen` / `await` / `forget` 观察，则在下一轮 `defer` 调用
  `Task.on_unhandled_rejection(reason, task)`（可 `set_unhandled_rejection` 覆盖）。

### WhenAll / WhenAny 策略

**WhenAll（近似 C# `Task.WhenAll`）**：

1. 等待**全部**子任务结算（不 fail-fast 打断等待）。
2. 若存在任一 **rejected** → 结果 **rejected**（取首个 reject reason）。
3. 否则若存在任一 **canceled** → 结果 **canceled**。
4. 否则 **fulfilled**，值为按输入顺序的结果数组。

即：**fault 优先于 cancellation 优先于 success**。

**WhenAny**：第一个结算的任务胜出；外层 **fulfilled**，payload 为
`{ index, value, status = "fulfilled"|"rejected"|"canceled", task }`
（便于调用方统一处理，而不把 WhenAny 本身变成 reject/cancel）。

## 6. 取消模型

| API | 作用 |
| --- | --- |
| `CancellationTokenSource` | `new` / `cancel` / `cancel_after` / `token` |
| `CancellationToken` | `is_cancellation_requested` / `throw_if_cancellation_requested` / `register` → unregister；`none` |
| `Cancellation.current` / `with_token` / `scope`（别名 `cancel_scope`） | ambient 栈；`scope` 链接父 token |
| `errors.canceled` / `{ canceled = true, ... }` | 取消错误形状 |

**UX**：优先 `Cancellation.scope(fn)` + 在 `Task.delay` 读 `Cancellation.current()`；显式 `ct` 参数仍保留。

**限制**：ambient 为进程级协作栈，**并行** `when_all` 时请显式传 ct；编译器按 `sm:step` 注入 ambient 留待后续。

`CTS:cancel_after(ms)` 与 `Task.delay` 共用调度路径。

## 7. 与协程方案对比

| | 本方言（状态机 + splice） | 典型 coroutine 方案 |
| --- | --- | --- |
| 文件形态 | Lua 宿主 + 嵌入 async | 通常全文件手写协程风格 |
| 挂起 | return Task，回调再入 step | yield / resume |
| 协程 | **不使用** | 核心依赖 |
