# 设计说明

本文说明 lua-async-dialect 的动机、方言与运行时分工、转译管线、状态机模型，以及与常见 Lua 协程异步库的对比。取消相关能力仅作规划，**当前不实现**。

## 1. 动机

Lua 里写异步常见两条路：

1. **显式回调 / Promise 链** —— 灵活但嵌套深、难审阅。
2. **`coroutine` + 调度器** —— 写法接近同步，但与宿主事件循环、可重入、调试栈绑定紧密，且「挂起点」依赖运行时约定。

本项目走第三条：**源码层提供 C# 风格 `async` / `await`，编译期降到表状态机 + Task**。

好处：

- 生成代码是普通 Lua 函数与表，无隐藏栈、无 `coroutine.resume`。
- 控制流在生成代码里可见（`_state`、`sm:step`），便于 code review。
- 运行时可嵌入任意「有微任务或手动 pump」的宿主，不强制协程调度器。

## 2. 方言 vs 运行时

| 层 | 职责 | 位置 |
| --- | --- | --- |
| **方言（.alua）** | 语法与语义约定：`async function`、`await` | `lib/*`、`transpile.lua` |
| **运行时（Task）** | Promise 风格结算、回调链、微任务队列 | `runtime/task.lua` |

转译器**只依赖** Task 的公开约定（`resolved` / `rejected` / `await_then` 等），不生成协程代码。业务侧也可手写 Task，不必经过方言。

## 3. 转译管线

```
.alua 源码
   │
   ▼
 Lexer（lib/lexer.lua）     → token 流（含行/列）
   │
   ▼
 Parser（lib/parser.lua）   → AST（file / async_fn / stmt / expr）
   │
   ▼
 Codegen（lib/codegen.lua） → 标准 Lua（状态机函数）
```

- **Lexer**：关键字、名字、数字、字符串、运算符；跳过空白与 `--` 行注释。
- **Parser**：递归下降；文件级只接受若干 `async function`；`await` 作为一元表达式。
- **Codegen**：按语句收集 `await`，把每个 await 边界切成状态；发出 `sm:step` 与 `Task.await_then`。

CLI（`transpile.lua`）串联三步并写文件或 `--stdout`。

## 4. 状态机模型：await 如何映射

对每个 `async function F(...)`，生成大致结构：

```lua
function F(...)
  local sm = { _state = 0, _locals = { ... } }
  function sm:step(ok, val)
    if not ok then return Task.rejected(val) end
    local s = self._state
    if s == 0 then
      -- 同步代码片段 …
      self._state = 1
      return Task.await_then(<被 await 的表达式>, self)
    elseif s == 1 then
      self._locals._aw0 = val   -- 上一 await 的结果
      -- 更多同步代码 …
      return Task.resolved(...)
    end
  end
  return sm:step(true)  -- 启动
end
```

要点：

1. **局部变量**放在 `sm._locals`，跨 await 存活（等价于「提升」到闭包字段）。
2. **每个 `await`**：先把内层表达式求值为 Task，再 `Task.await_then`；结算成功则 `step(true, v)`，失败则 `step(false, e)`。
3. **状态编号**：线性递增；进入状态 `k>0` 时，把上一状态 await 的 `val` 写入临时名 `_awN`，再赋给用户变量。
4. **表达式内多个 await**：按求值顺序拆成多个 await op，再按边界切状态（当前 MVP 无短路逻辑运算符）。
5. **无协程**：挂起 = `return` 一个尚未结算的 Task 链；恢复 = 回调里再次调用 `sm:step`。

拒绝路径统一：`ok == false` 时直接 `Task.rejected(val)`，不继续后续状态。

## 5. Task 运行时

### 生命周期

- `pending`：尚未结算；可登记 `_ok_cbs` / `_err_cbs`。
- `fulfilled` / `rejected`：终态；`resolve` / `reject` 对非 pending 为幂等空操作。

### 核心 API

| API | 作用 |
| --- | --- |
| `Task.new()` | 新建 pending Task |
| `Task.resolved(v)` / `Task.rejected(e)` | 已结算工厂 |
| `Task:resolve` / `Task:reject` | 结算并经 `defer` 触发回调 |
| `Task:andThen(ok, err)` | 链式；回调可返回值或嵌套 Task（会扁平化） |
| `Task.await_then(task, sm)` | `andThen` 特化：结算后 `sm:step(ok, …)` |
| `Task.defer(fn)` / `Task.pump()` | 微任务队列；避免同步回调重入过深 |

`andThen` 内用 `pcall` 包住用户回调；抛错视为 reject。若回调返回带 Task 元表的表，则继续 `andThen` 接到输出 Task。

Demo（`run_demo.lua`）在结果打印前循环 `Task.pump()`，直到链结算或达到守卫次数。

## 6. 与 Lua 协程异步库的对比（简要）

| | 本方言（状态机） | 典型 coroutine 方案 |
| --- | --- | --- |
| 挂起机制 | `return` Task，回调再入 `step` | `coroutine.yield` / 包装 resume |
| 栈与调试 | 生成代码显式状态；栈是回调栈 | 协程独立栈；需调度器配合 |
| 与 C/宿主 | 不依赖 resume 时机 | 常需「在正确线程 resume」 |
| 源码观感 | 需转译；.alua 接近 async/await | 可直接在 Lua 里写「同步风」 |
| 取消 | 规划中（见下）；未做 | 各库自有约定，差异大 |

本项目**刻意不用** `coroutine`，以便生成物与运行时契约简单、可嵌入无协程宿主。

## 7. 未来：取消（仅规划，不实现）

方向性想法（**当前仓库无代码**）：

- **`cancel_scope`**：划定可取消区域；进入/离开时维护作用域栈。
- **Ambient token**：await 点隐式读取当前 token；若已取消则走 reject / 专用取消错误，而不继续下一状态。
- 与 Task 的关系：可能给 pending Task 增加 `cancel`，或仅在 `await_then` 入口检查 token。

在 MVP 落地取消前，所有 await 均假设「一直跑到结算」；调用方需自行避免泄漏的长任务。
