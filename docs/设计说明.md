# 设计说明

本文说明 lua-async-dialect 的动机、**嵌入式方言**模型、转译管线（splice）、状态机与控制流降级，以及与协程方案的对比。取消能力仅作规划，**当前不实现**。

## 1. 动机

Lua 里写异步常见两条路：显式回调 / Promise 链，或 `coroutine` + 调度器。本项目走第三条：**源码层提供 C# 风格 `async` / `await`，编译期降到表状态机 + Task**，且把方言嵌在标准 Lua 宿主文件中，避免「整个文件都是受限方言」。

## 2. 嵌入式方言模型

`.alua` 类似「Makefile 嵌入 recipe」：

- **宿主**：大部分源码是**逐字透传**的标准 Lua（表、普通 `function`、`if`/`for`、`require` 等）。
- **方言块**：仅顶层 `async function Name(...) ... end` 被抽出，走 Lexer → Parser → Codegen。
- **顺序**：透传块与生成块按源码出现顺序拼接；若存在任一 async，在输出**最顶部**插入一次 `local Task = require("runtime.task")`。

实现见 `lib/splice.lua`：字符级扫描，跳过字符串与 `--` / `--[[ ]]` 注释，按 Lua 块关键字匹配 `end`（`function`/`if`/`do`/`repeat` 加深；`while`/`for` 本身不加深，由其 `do` 加深）。

| 层 | 职责 | 位置 |
| --- | --- | --- |
| **Splice** | 找 async 区域、透传、拼装 | `lib/splice.lua` |
| **方言** | async 体内语法与语义 | `lib/lexer.lua` 等 |
| **运行时** | Task 结算与微任务 | `runtime/task.lua` |

## 3. 转译管线

```
.alua 源码
   │
   ▼
 Splice 扫描          → text 块 | async 块（保持顺序）
   │
   ├─ text 块 ──────────────────────────► 原样写入输出
   │
   └─ async 块
         │
         ▼
       Lexer → Parser → Codegen.generate_function
         │
         ▼
       状态机 function 源码 ────────────► 写入输出
```

CLI：`transpile.lua` 调用 `Splice.transpile`。

## 4. 状态机模型

每个 `async function` 生成：

```lua
function F(...)
  local sm = { _state = 0, _locals = {}, _await_tmp = nil }
  function sm:step(ok, val)
    if not ok then return Task.rejected(val) end
    if self._await_tmp then
      self._locals[self._await_tmp] = val
      self._await_tmp = nil
    end
    while true do  -- 同步 goto / branch 在同一次 step 内消化
      local s = self._state
      -- ... 按 s 执行 codes，然后 await / return / 改 _state ...
    end
  end
  return sm:step(true)
end
```

要点：

1. **局部量**在 `sm._locals`，跨 await 存活。
2. **await**：设置 `_state` 与 `_await_tmp`，`return Task.await_then(...)`；恢复时写入临时名。
3. **if / while / for**：先降为 label / branch / goto 微操作，再切成基本块状态；分支内可含 await。
4. **无协程**：挂起 = return Task；恢复 = 回调再入 `step`。

`and`/`or` 中的 await 按求值顺序**预先**拆出（非短路侧也可能先 await）；条件本身的短路在生成代码的 `and`/`or` 上仍由 Lua 执行。

## 5. Task 运行时

与先前相同：`pending` → `fulfilled`/`rejected`；`andThen`、`await_then`、`defer`/`pump`。详见 `runtime/task.lua`。

## 6. 与协程方案对比

| | 本方言（状态机 + splice） | 典型 coroutine 方案 |
| --- | --- | --- |
| 文件形态 | Lua 宿主 + 嵌入 async | 通常全文件手写协程风格 |
| 挂起 | return Task，回调再入 step | yield / resume |
| 协程 | **不使用** | 核心依赖 |
